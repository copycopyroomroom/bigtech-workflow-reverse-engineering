# Big Tech Workflow Reverse Engineering

공개 오픈소스 저장소의 커밋·PR·리뷰·릴리스 기록을 근거로 개발 워크플로우를 분석하고, **AI가 여러 프로젝트의 관행을 대상 팀에 맞춰 조합·수정·제안하는 도구**를 만드는 프로젝트입니다. 공개 연구와 워크플로우 자문에서 사용할 수 있도록 근거·한계·검토 상태를 추적합니다.

`공개 기록 → 근거와 주장 → 관행 모듈 → 팀별 대안 → 대화 수정·검사 → 운영 문서·적용 실험`

## 원칙

- 연구의 원천 데이터는 공개적으로 접근 가능한 자료만 사용합니다. 사용자가 제공하는 팀 정보는 공개 연구 자료와 분리합니다.
- 개인 개발자에 대한 평가·프로파일링보다 팀 단위의 프로세스 패턴에 집중합니다.
- 관찰된 사실과 해석·추론을 명확히 구분합니다.
- 회사별 상표·공식 입장과 혼동되지 않도록 독립 연구임을 표시합니다.
- 각 분석 결과에는 데이터 출처, 기간, 표본 기준과 한계를 기록합니다.
- 관찰된 관행, 기대 효과 가설, 대상 팀에서 확인한 효과를 구분합니다.
- AI 신규 제안과 기존 관행의 변형을 표시하고, 필수 제약·의존·충돌·역할 부담을 검사합니다.

## 세 가지 사용 옵션

우선순위를 고정하지 않고 공통 엔진 위에서 모두 선택할 수 있게 설계합니다.

| 옵션 | 사용하는 방식 |
| --- | --- |
| 팀 직접 사용 | 팀이 입력·대안 비교·수정·내보내기·자체 실험을 수행 |
| 자문 도구 | 자문자가 인터뷰·진단·근거 검토·설계·실험 계획을 지원 |
| 함께 사용 | 팀의 직접 사용과 선택 범위의 자문 검토·인수인계를 결합 |

각 옵션에서 `최소 변경 / 균형 / 통제 강화` 대안을 비교합니다. 사용 모드와 추천 대안은 서로 다른 선택입니다.

## 계획과 분석 대상

여러 분야를 균형 있게 비교하기 위해 6개 카테고리별로 후보 저장소 3개씩, 총 18개를 정리했습니다. 첫 연구는 분야별 1개씩 6개 저장소를 점검한 뒤 진행합니다.

- [실행 계획안](PLAN.md): 목표, 1차 대상, 세 사용 모드, 약 20주 단계별 일정과 완료 조건.
- [회사·카테고리별 저장소 후보](REPOSITORIES.md): 18개 후보, 회사 관계, 현재 운영 맥락과 분석 질문.
- [분석 프로토콜](methodology/ANALYSIS_PROTOCOL.md): 수집 범위, 표본 추출, 지표 정의와 검증 규칙.
- [AI 워크플로우 설계 기능](product/WORKFLOW_COMPOSER.md): 팀 입력, 관행 조합, 대화 수정·diff·잠금, 내보내기와 MVP.
- [플랫폼 구현 설계](architecture/PLATFORM.md): Next.js·FastAPI·PostgreSQL 기준안, 화면·API·작업 처리·고객 격리·배포와 추가 일정.
- [입출력 계약](specs/WORKFLOW_CONTRACTS.md): 근거·주장·모듈·팀·제안·검증 이력의 필드와 규칙.
- [평가와 공개·자문 기준](quality/EVALUATION.md): 고정 평가 세트, 기준선 비교, 품질 게이트와 비용.
- [자문 절차](advisory/ENGAGEMENT.md): 진단, 대안 비교, 검토·파일럿·후속 수정의 납품 기준.
- [가상 조합 예시](examples/COMPOSITION_WALKTHROUGH.md): 수정·충돌·보류가 어떻게 동작할지 보여주는 설계 사례.
- [참고 자료](REFERENCES.md), [기여·정정 안내](CONTRIBUTING.md).

분석 단위는 특정 저장소의 특정 기간입니다. 프로젝트를 시작한 회사와 현재 운영 주체를 구분하며, 공개 저장소의 관찰을 회사 전체의 개발 방식으로 일반화하지 않습니다.

## 상태

기획 v0.3입니다. 후보 목록, 분석 방법, AI 조합 기능·계약, 평가·자문 절차와 플랫폼 기술 기준안을 작성했습니다. 기능 구현·데이터 수집·성능 평가·외부 검토·현장 실험은 아직 진행하지 않았습니다.

첫 구현은 라이브러리·CLI와 파일 입출력으로 계획하며, 현재 설치하거나 실행할 제품은 없습니다. 공개 도구 출시와 사람 검토된 자문, 실제 팀의 효과 검증은 별도로 판정합니다.

공통 엔진은 약 20주, 후속 웹 플랫폼은 추가 약 14주를 잠정 추정합니다. 두 범위의 의존성과 병행 가능성을 초기 구현 후 다시 산정하며 고정 납기나 검증된 개발 속도를 뜻하지 않습니다.
